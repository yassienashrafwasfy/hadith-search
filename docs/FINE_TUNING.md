# Fine-Tuning Methodology

> This document describes the fine-tuning strategy, rationale, hyperparameters, and expected outputs for the three LoRA experiments that form the core contribution of the paper.

---

## Overview

The base embedding model is `intfloat/multilingual-e5-large`, a 560M-parameter multilingual sentence embedding model. It was pretrained on a large collection of multilingual text pairs using contrastive learning, and it supports 100+ languages including both English and Arabic.

Despite strong general performance, E5 was not trained on Islamic religious texts. Its embedding space may not capture:
- Domain-specific Arabic vocabulary (fiqh terminology, hadith-specific expressions)
- Semantic relationships between Islamic concepts as expressed in hadith style
- Cross-lingual alignment for Islamic queries (an Arabic query about "فضل الصيام" and an English query about "virtue of fasting" should retrieve similar hadiths)

The fine-tuning experiments test whether domain-specific adaptation via LoRA improves retrieval on this specialized corpus.

---

## Why LoRA

**Parameter-Efficient Fine-Tuning (PEFT)** with LoRA (Low-Rank Adaptation) is used instead of full model fine-tuning for two reasons:

1. **Resource constraints**: Full fine-tuning of a 560M-parameter model requires significantly more GPU memory and training time. LoRA adds small trainable rank-decomposition matrices to the attention layers while freezing the original weights, reducing trainable parameters by ~99%.

2. **Catastrophic forgetting**: Full fine-tuning on a small domain dataset risks degrading the model's general multilingual capabilities. LoRA adapters are additive and leave the base model weights unchanged, limiting forgetting.

**LoRA configuration**:

| Parameter | Value | Rationale |
|-----------|-------|-----------|
| Rank (r) | 16 | Standard starting point for sentence embedding adaptation |
| Alpha | 32 | Alpha = 2×r is a common heuristic for stable training |
| Dropout | 0.1 | Light regularization for a small dataset |
| Target modules | Query and value projection layers | Standard for BERT-architecture models |

All parameters are overridable via environment variables (`LORA_R`, `LORA_ALPHA`, `LORA_DROPOUT`).

---

## Loss Function: Multiple Negative Ranking Loss (MNRL)

Fine-tuning uses **Multiple Negative Ranking Loss (MNRL)** with in-batch negatives.

Given a batch of (query, positive document) pairs, each positive document in the batch serves as a negative for every other query in the batch. The model is trained to maximize the similarity between each query and its correct positive, and minimize similarity with all in-batch negatives.

**Temperature**: 0.05 (env: `MNRL_TEMPERATURE`). Lower temperature sharpens the similarity distribution, making the task harder and producing better-calibrated embeddings.

**Why MNRL for this task**:
- Efficient: no explicit hard negative mining required; in-batch negatives scale with batch size
- Well-suited for (query, document) pairs without fine-grained relevance scores
- Used successfully for sentence embedding fine-tuning in prior work

## Training Data Sources

### Source 1: LLM-Graded Qrels (`training_qrels_graded.json`)

100 training queries (50 English, 50 Arabic) are graded by an LLM against pooled hadith candidates. Each (query, hadith) pair is scored relevant (1) or not (0).

Positive pairs for MNRL training: all (query, hadith) pairs where the LLM assigned relevance >= 1. Passages are read from canonical database matn, including KV pairs, and formatted as `passage: {Matn}`. Arabic passages receive the same light normalization as Arabic queries. Full text, chapter titles, and isnad are not used as the positive passage.

The LLM grader is validated against human judgments on the 20 eval queries (see `docs/EVALUATION.md`). A Cohen's Kappa ≥ 0.40 is required to justify using LLM grades as training signal.

**File**: `backend/data/training_qrels_graded.json`  
**Generated by**: `backend/scripts/llm_grader.py`

### Source 2: Verified KV Pairs (`kv_pairs_verified.json`)

Concept-entity pairs are extracted from hadith matn text by an LLM. Each pair associates an Islamic concept (e.g., "the ruling on fasting during travel") with the hadith that discusses it. After human verification via the web UI, these pairs form (concept-query, hadith-passage) training instances.

**Rationale**: E5 was pretrained on general-domain text pairs. It has not seen Islamic fiqh concepts expressed in the style used by query users. KV pairs teach the model to associate domain-specific Islamic concept phrasings with the relevant hadith text. This is a form of domain vocabulary alignment — training the embedding space to understand "what Islamic concepts look like as queries" by grounding them in verified relevant hadiths.

**Scale**: ~1000 verified pairs across 10 Islamic topics.

**File**: `backend/data/kv_pairs_verified.json`  
**Generated by**: `backend/scripts/kv_generator.py` + human verification at `/dev/kv-pairs`

## The Three Fine-Tuning Modes

### Mode 1: `triplet`

**Training data**: LLM-graded qrels only (`training_qrels_graded.json`)  
**Training pairs**: (query text, matn-only passage) for each graded-relevant (query, hadith) pair  
**Hypothesis**: Standard IR fine-tuning signal (query → relevant document) is sufficient to improve E5 for hadith retrieval.

This is the baseline fine-tuning mode. It is the most similar to how dense retrieval models are typically fine-tuned (e.g., DPR, ColBERT).

### Mode 2: `kv_pairs`

**Training data**: Verified KV pairs only (`kv_pairs_verified.json`)  
**Training pairs**: (concept text, matn text) for each verified pair  
**Hypothesis**: Domain vocabulary alignment via concept-entity pairs improves retrieval independently of qrel-based fine-tuning, particularly for queries that use Islamic fiqh terminology.

This is the novel fine-tuning signal. If KV pairs outperform or match qrel-based fine-tuning despite using no human relevance judgments, this suggests a cheap and scalable alternative to annotation for domain adaptation of embedding models.

### Mode 3: `combined`

**Training data**: Both `training_qrels_graded.json` and `kv_pairs_verified.json`, merged  
**Training pairs**: Union of triplet and kv_pairs training instances, shuffled  
**Hypothesis**: Combining both signals (IR supervision + domain vocabulary alignment) achieves the best retrieval performance.

## Training Procedure

```
for each mode in [triplet, kv_pairs, combined]:
    1. Load intfloat/multilingual-e5-large
    2. Apply LoRA config → trainable adapter layers
    3. Load training pairs
    4. Split 85% train / 15% validation (fixed seed=42)
    5. Train with MNRL loss, batch_size=16
    6. Evaluate on validation set after each epoch
    7. Early stopping if validation loss does not improve for 3 consecutive epochs
    8. Save best adapter to backend/data/finetuned/{mode}/
    9. Save training_history.json
```

**Run commands** (from `backend/`, with GPU):

```powershell
python scripts\finetune.py --mode triplet
python scripts\finetune.py --mode kv_pairs
python scripts\finetune.py --mode combined
```

**GPU requirement**: CUDA required for reasonable training speed. CPU fallback is possible but will take many hours per mode.

---

## Evaluation of Fine-Tuned Adapters

After training, each adapter is evaluated by:

1. Loading the base E5 model with the LoRA adapter applied
2. Re-encoding all hadith passages with the adapted model
3. Running all E5-dependent retrieval systems (cosine, semantic rerank, RRF) against the new embeddings
4. Computing IR metrics against human-graded qrels

**Run command**:

```powershell
python scripts\finetune_eval.py --mode triplet   # repeat for kv_pairs, combined
```

Output: `backend/data/finetuned_results_{mode}.json`

**Important**: Each `finetune_eval.py` run overwrites the embedding arrays. After evaluating all three modes, rebuild baseline embeddings:

```powershell
python scripts\build_embeddings.py
```
